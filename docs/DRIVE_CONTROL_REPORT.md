# Отчёт: асимметрия тяги и медленное торможение

**Дата:** 18 сентября 2026  
**Автор:** Kilo Code Assistant  
**Ревизия кода:** `cc50941`  
**Файлы контура:** `firmware/src/control.rs` (каскадный контроллер), `firmware/src/main.rs` (цикл 200 Гц)

---

## 1. Симптомы

1. **Асимметрия тяги.** Если робот заармлен с наклоном (точка баланса «завалена» куда-то), то для езды в одну сторону приходится выжимать стик сильно, а в другую — робот срывается с места от малейшего отклонения.
2. **Медленное торможение.** После разгона при отпускании стика робот останавливается вяло; хочется резче.

---

## 2. Как устроен контур хода сейчас

`control.rs::update()` (200 Гц), каскад: **стик → целевая скорость → наклон → контур баланса**:

```rust
// 1. Стик задаёт ЦЕЛЬ СКОРОСТИ (не наклон!)
let commanded_velocity = drive_forward * MAX_CRUISE_SPEED;   // 4800 шаг/с

// 2. S-профиль: цель наращивается/снижается плавно
//    TARGET_SLEW_RATE = 6000 шаг/с², S_CURVE_JERK = 15000 шаг/с³
//    (одинаковая скорость роста и снижения)

// 3. Наклон пропорционален недобору скорости (чистый P, без интеграла!)
let speed_error = self.target_velocity - wheel_rate_logical;
let base_lean = (g.kd_vel * speed_error)                    // kv = 0.001 °/(шаг/с)
    .clamp(-max_drive_lean_deg, max_drive_lean_deg);        // ±3° (параметр drive_lean)

// 4. Итоговый наклон ограничен, дальше — контур баланса (ka/kd/ki)
let lean = lean.clamp(-g.max_lean_deg, g.max_lean_deg);     // ±9° (параметр lean)
let err = (angle_deg - target_angle) - lean;                // target_angle = trim + trim_offset
```

Ключевые константы: `MAX_CRUISE_SPEED = 4800` шаг/с (~1.3 об/с), `kv = 0.001`, `drive_lean = 3°`, `TARGET_SLEW_RATE = 6000` (симметрично для разгона и торможения).

## 3. Причина асимметрии: трим ≠ физическое равновесие

### Механика

При арминге трим запоминается по углу, в котором держали робота: `angle_trim = held_angle`. Если робота держали не вертикально (или он стоит на уклоне), трим отличается от истинного равновесия на Δ.

Дальше физика: отклонение наклона от истинного равновесия создаёт постоянное «скатывание». Чтобы удерживать заданную скорость, контуру нужен **постоянный наклон L** против этого скатывания. Но в контуре скорости нет интегратора — только P:

```
lean = kv · (v_цель − v_факт)   →   в установившемся режиме:
v_факт = v_цель − L / kv
```

**Числа:** при Δ, требующем L = 1.5°, и kv = 0.001:

```
смещение скорости = L / kv = 1.5 / 0.001 = 1500 шаг/с ≈ 31% крейсерской!
```

То есть в одну сторону робот едет на **1500 шаг/с медленнее** команды (стик «вялый» — сколько ни выжимай, скорость не набирается), а в другую — на **1500 шаг/с быстрее** команды (гиперчувствительность). Хуже того: постоянная составляющая L съедает бюджет наклона несимметрично — в «тяжёлую» сторону остаётся `3° − 1.5° = 1.5°`authority, в «лёгкую» — `3° + 1.5°`.

### Почему «много тяги» не помогает

Стик задаёт **целевую скорость**, а не наклон. Когда цель недостижима (бюджет наклона исчерпан), дальнейшее отклонение стика вообще ничего не меняет: `speed_error` уже сатурировал `base_lean` на ±3°. Ощущение «надо давить сильнее» — иллюзия: контроллер уже просит максимум.

### Почему существующая адаптация не спасает

`adapt_trim()` доучивает трим, но только **в покое**: она работает от `lean_from_position` (удержание точки стоянки), а при езде `position` сбрасывается в 0 и адаптация ничего не получает. Пока робот стоит, трим сходится к истинному равновесию (`TRIM_ADAPT_RATE = 0.45 °/с`, предел ±6° от `trim_base`) — но сразу после арминга с наклоном или на уклоне во время езды коррекции нет.

### Как увидеть в UI

Осциллограф, канал `lean` (в телеметрии это `term_lean`): если при ровном полу и постоянной скорости lean висит у ±3° (сатурация) — это оно. Признак также: робот «уезжает» при нулевом стике, пока не отработает удержание позиции.

## 4. Причина медленного торможения

Два независимых ограничения, оба симметричны разгону:

1. **S-профиль снижает цель с той же скоростью, что наращивает**: `TARGET_SLEW_RATE = 6000 шаг/с²` + сглаживание рывка `S_CURVE_JERK = 15000`. Торможение с крейсера 4800 шаг/с занимает ≥ 0.8 с только на рампу цели, фактически ~1 с и больше.
2. **Тормозной наклон ограничен тем же ±3°** (`drive_lean`), что и разгонный — хотя торможение безопаснее разгона (робот отклоняется против движения, а не разгоняется прочь).

Отдельно: защитный тормоз `SPEED_BRAKE_RATE` (при упоре в стену) — не про это, он не участвует в штатном выбеге.

## 5. Предлагаемые изменения

### A. Интегратор контура скорости — адаптация трима на ходу ⭐⭐⭐⭐⭐ (главное)

**Файл:** `control.rs::update()` + параметр. **Трудозатраты:** 2–3 ч. **Риск:** низкий-средний.

Когда цель по скорости достигнута (ошибка мала), постоянная составляющая наклона медленно «переучивается» в трим — как это уже делает `adapt_trim` в покое, но по скорости:

```rust
const DRIVE_TRIM_ADAPT_RATE: f32 = 0.2;  // °/с на 1° постоянного наклона
const DRIVE_TRIM_ADAPT_ERR: f32 = 500.0; // адаптируем только у цели (шаг/с)

if speed_error.abs() < DRIVE_TRIM_ADAPT_ERR {
    self.angle_trim += base_lean * DRIVE_TRIM_ADAPT_RATE * dt;
    self.angle_trim = self.angle_trim.clamp(
        self.trim_base - TRIM_MAX_DRIFT_DEG,
        self.trim_base + TRIM_MAX_DRIFT_DEG,
    );
}
```

**Эффект:** за ~5–10 с езды трим сходится к истинному равновесию (на уклоне — к равновесию на уклоне), бюджет наклона центрируется, тяга становится симметричной в обе стороны. На уклоне робот начнёт стоять наклонённым — это правильно.

**Защиты:** адаптация только у цели (не мешает разгону), скорость ограничена, предел ±6° от точки арминга — те же оговоры, что у штатной адаптации в покое.

**Параметр:** `trim_adapt_drive` (0..1, по умолчанию 0.2) — 0 отключает.

### B. Асимметричный S-профиль: торможение быстрее разгона ⭐⭐⭐⭐

**Файл:** `control.rs::update()`. **Трудозатраты:** ~1 ч. **Риск:** низкий.

Отдельная скорость снижения цели (газ сброшен — `|commanded| < |target|` или смена знака):

```rust
const BRAKE_SLEW_RATE: f32 = 15000.0;  // торможение в 2.5 раза быстрее разгона
```

Выбег с крейсера сокращается с ~1 с до ~0.4 с. Опционально: при смене знака стика (разгон → реверс) цель сбрасывается к 0 немедленно, без рампы.

**Параметр:** `brake_rate` (1..4, по умолчанию 2.5) — множитель к `TARGET_SLEW_RATE`.

### C. Тормозной наклон ⭐⭐⭐

**Файл:** `control.rs::update()`. **Трудозатраты:** 1–2 ч. **Риск:** средний — слишком агрессивно → раскачка/падение вперёд.

При торможении разрешить наклон до `min(1.5 × drive_lean, max_lean)` (4.5° при текущих настройках, всё ещё вдвое ниже предельного 9°). Вводить осторожно, с шагом ×1.2, проверяя на ровном полу.

**Параметр:** `brake_lean` (1.0..2.0, по умолчанию 1.5) — множитель к `drive_lean` при торможении.

### D. (Опционально) Прямой feedforward наклона от стика ⭐⭐

```
lean = clamp(kv·speed_error + kff·stick·drive_lean, ±drive_lean)
```

Даёт «прямое» ощущение: отклонение стика = немедленный наклон, независимо от достижения цели. **Не рекомендую делать первым**: меняет характер управления (контур скорости теряет монополию на наклон), может конфликтовать с A. Имеет смысл только если после A останется желание «более прямой связи».

### E. Телеметрия/дашборд ⭐⭐⭐

- В дашборд вывести `lean` (уже передаётся как `term_lean`) рядом с углом — сатурация видна сразу.
- Вывести текущий `trim` (уже есть) и признак «трим адаптируется».
- Это ускорит диагностику подобных жалоб в будущем.

## 6. Что можно сделать уже сейчас (без прошивки)

1. **Армить робота вертикально** — держать его строго прямо при включении баланса: трим = истинное равновесие, асимметрии нет.
2. **Дать постоять 10–20 с** после арминга — штатная `adapt_trim` в покое доучит трим (0.45 °/с).
3. **Подправить трим геймпадом** (D-pad ↑↓, ±0.1° за нажатие): ехать медленно в «тяжёлую» сторону и нажимать, пока тяга не сравняется.
4. Поднять `drive_lean` (3° → 4–5°) в тюнинге — больше бюджета в обе стороны, но не лечит причину.

## 7. План проверки после реализации

| Тест | Что делаем | Что ждём |
|---|---|---|
| Симметрия на ровном полу | Заармить с завалом ~3°, проехать в обе стороны на одинаковой тяге | После A: за ~10 с езды скорости выравниваются, lean уходит из сатурации |
| Уклон | Поставить на пандус/наклонную доску, ехать вверх/вниз | Скорости симметричны, робот стоит на уклоне наклонённым (трим = равновесие уклона) |
| Выбег | Разгон до полного стика, отпустить стик, замерить дистанцию выбега (по `steps`) | После B: выбег сокращается примерно вдвое; после C — ещё на ~30% |
| Раскачка | Серия разгон-торможение на максимальной тяге | Нет колебаний угла > 5° после остановки, детектор падения не срабатывает |
| Возврат трима | После езды на уклоне вернуться на ровный пол, постоять | Трим возвращается к вертикали штатной адаптацией в покое |

Контрольные каналы в осциллографе: `Angle`, `lean` (term_lean), `WheelRate`, `Trim`.

Обе жалобы — следствия одного архитектурного факта: **контур скорости — чистый P-регулятор с симметричными ограничениями**. A закрывает отсутствие интеграла (асимметрия), B+C — симметрию ограничений (торможение).

**Новые параметры** (все в тюнинге UI, применяются сразу, сохраняются в NVS):

| Параметр | Диапазон | По умолчанию | Действие |
|---|---|---|---|
| `trim_adapt` | 0..1 | 0.2 | °/с на 1° постоянного наклона у цели → трим; 0 = выкл |
| `brake_rate` | 1..4 | 2.5 | Множитель скорости снижения цели при торможении |
| `brake_lean` | 1..2 | 1.5 | Множитель drive_lean при торможении (≤ lean) |
| `drive_ff` | 0..1 | 0 | Прямая связь стик→наклон; 0 = выкл (рекомендуется с trim_adapt) |
